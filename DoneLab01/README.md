## Задание 1. Глоссарий терминов

*Источник: Конспект лекций по дисциплине «Языки программирования», ИМИТ ИГУ, 2026 г. (автор: Кириченко К.Д.)*

### Виды программного кода
* **Исходный код** — текст программы на языке программирования (высокого уровня).
* **Объектный код** — переходный файл (результат трансляции одного модуля), содержащий команды на языке исполнителя и имена идентификаторов, но ещё не объединённый в исполняемый файл.
* **Исполняемый код (исполняемый файл)** — файл, содержащий программу в виде набора элементарных инструкций, которая после загрузки в память может быть выполнена на определенном физическом устройстве под управлением операционной системы.

### Фундаментальные понятия и аспекты
* **Прагматика** — аспект языка программирования, отвечающий на вопрос: *«Что я хочу получить?»*.
* **Семантика** — аспект языка программирования, определяющий смысловое значение конструкций и отвечающий на вопрос: *«Как это будет работать?»*.
* **Синтаксис** — правила построения конструкций языка, отвечающие на вопрос: *«Как мне это написать?»*.
* **Язык низкого уровня** — язык программирования, на котором можно непосредственно написать программу, исполняемую на физическом устройстве.
* **Ассемблер** — язык программирования низкого уровня, в котором каждая инструкция физического устройства представлена в текстовом виде.
* **Язык высокого уровня** — язык, абстрагирующийся от элементарных команд процессора и позволяющий записывать программы в виде функций, алгоритмов, классов и структур данных.
* **Стандарт языка программирования** — документ, описывающий язык программирования максимально подробно и формально для согласования правил написания и исполнения программ.
* **Устаревшие возможности (Deprecated)** — возможности языка, отменённые или не рекомендуемые к использованию в более новых стандартах.

### Виртуальные машины и трансляция
* **Виртуальная машина языка программирования** — средство описания семантики языка, определяющее работу синтаксических конструкций, правила их использования и поведение при нарушениях.
* **Байт-код (промежуточное представление)** — набор инструкций, близких по смыслу к машинному коду, выполняемый на виртуальной машине.
* **Транслятор** — техническое средство, осуществляющее перевод текста программы с одного языка на другой.
* **Компилятор** — транслятор, переводящий программу в машинный код для последующего исполнения.
* **Интерпретатор** — транслятор, читающий и исполняющий программу по одной команде.
* **Псевдокомпилятор** — транслятор, переводящий программу в промежуточное представление (байт-код).
* **Компилирующий интерпретатор** — транслятор, переводящий текст программы во внутреннее представление непосредственно после запуска.
* **REPL-интерпретатор (Read-Eval-Print Loop)** — программное средство, работающее в интерактивном цикле «чтение — вычисление — печать».
* **Единица трансляции** — минимальный фрагмент программы, который может быть транслирован независимо от остального кода.

### Этапы жизненного цикла и инструментарий
* **Предобработка (Препроцессинг)** — начальный этап трансляции, выполняющий макроподстановки по заданным правилам.
* **Синтаксический анализ и генерация кода** — проверка синтаксиса и создание объектного кода или внутреннего представления.
* **Оптимизация кода** — преобразование кода для повышения эффективности работы программы.
* **Сборка (Связывание / Линковка)** — объединение отдельных объектных файлов и библиотек в единый исполняемый файл.
* **Загрузка** — размещение программы в памяти для последующего исполнения.
* **Выполнение** — непосредственное исполнение команд программы.
* **Директива препроцессора** — команда препроцессору, начинающаяся с символа `#`.
* **Условная трансляция (`#ifdef`, `#ifndef`)** — механизм, позволяющий включать или исключать фрагменты кода из трансляции.
* **Утилита `make`** — инструмент для управления процессом компиляции и сборки программ на основе файла зависимостей `makefile`.

### Ошибки и поведение программы
* **Синтаксические ошибки** — ошибки, обнаруживаемые транслятором на этапе проверки синтаксиса.
* **Ошибки сборки** — ошибки, возникающие при отсутствии одного из компонентов программы на этапе линковки.
* **Ошибки времени выполнения (Run-time error)** — ошибки использования виртуальной машины, обнаруживаемые непосредственно в момент выполнения (например, деление на ноль).
* **Непредсказуемое поведение** — состояние программы, при котором неверное использование виртуальной машины приводит к ошибкам в непредсказуемый момент.
* **Неопределенное поведение (Undefined Behavior)** — ситуация, когда поведение программы однозначно, но не определено описанием языка, что приводит к разным результатам на разных трансляторах.


## Задание 2. Работа с файловым менеджером Far Manager

### Справка по горячим клавишам Far Manager
При выполнении операций с файлами и каталогами использовались следующие горячие клавиши (без использования мыши):

* `F7` — создание новой папки (каталога).
* `Shift + F10` / `Shift + F11` — создание нового файла или вызов меню создания объектов.
* `F4` — открытие выделенного файла во встроенном текстовом редакторе.
* `F3` — просмотр содержимого файла без возможности редактирования.
* `F5` — копирование выделенного файла или папки в соседнюю панель.
* `F6` — перемещение или переименование файла/папки.
* `F8` / `Delete` — удаление выделенного файла или папки.
* `Enter` — переход в каталог или запуск исполняемого файла / выполнение команды в командной строке.
* `Tab` — переключение фокуса между левой и правой панелями.
* `Ctrl + O` — скрытие/отображение панелей для просмотра консольного вывода.
* `Alt + F1` / `Alt + F2` — смена диска или текущего пути для левой / правой панели соответственно.
* `Esc` — отмена текущей операции или очистка командной строки.

### Задание 3. Компиляция C++ из командной строки
Для компиляции программы на C++ используется компилятор `g++`. Опция `-o` указывает имя итогового исполняемого файла (`.exe`). Настройка переменной окружения `Path` позволяет операционной системе находить исполняемый файл компилятора из любой директории командной строки без указания полного пути.

### Задание 4. Раздельная компиляция в C++
Разделение программы на заголовочные файлы (`.h`) с объявлениями и файлы реализаций (`.cpp`) позволяет выполнять **раздельную трансляцию**. С помощью ключа `-c` каждый модуль компилируется в независимый **объектный файл** (`.o`). После этого компоновщик (линкер) объединяет объектные файлы в единый исполняемый файл. При ошибке в одном модуле не удастся собрать итоговый файл, но исправный модуль можно скомпилировать отдельно.

### Задание 5. Раздельная компиляция в Java
В Java единицей трансляции является публичный класс (файл `.java`). Псевдокомпилятор `javac` транслирует каждый исходный файл в независимый **байт-код** (файл `.class`). Исполнение и связывание классов происходит во время выполнения на виртуальной машине Java (JVM) с помощью команды `java`.

### Задание 6. Модульность в Python
В Python единицей трансляции выступает отдельный файл-модуль (`.py`). Подключение функций из других файлов выполняется с помощью инструкции `import`. Python является компилирующим интерпретатором: при первом импорте модуль автоматически транслируется во внутреннее представление (байт-код), после чего сразу интерпретируется и выполняется.

### Задание 7. Автоматизация сборки с помощью make
Утилита `make` автоматизирует процесс компиляции на основе инструкций из `makefile`. Она строит дерево зависимостей и сравнивает время последнего изменения исходных файлов и целей. Благодаря этому `make` выполняет **инкрементальную сборку** — пересобирает только те модули, которые были изменены, экономя время компиляции.

### Задание 8. Стандарты языка C++
Язык C++ развивается через принятие стандартов (C++98, C++03, C++11, C++14, C++17). Новые стандарты вводят новые синтаксические конструкции (автовывод типов `auto`, диапазоны `for (auto x : v)`, списки инициализации, двоичные литералы и CTAD). Флаг `-std=c++XX` указывает компилятору `g++`, правила какого стандарта использовать при трансляции кода.

### Задание 9. Оптимизация кода компилятором
Флаги оптимизации (`-O0`, `-O1`, `-O2`, `-O3`) задают уровень преобразования кода компилятором:
* **`-O0`** — оптимизация отключена; сгенерированный ассемблерный код точно повторяет структуру исходного текста (включая явные циклы и инкременты).
* **`-O1` / `-O2`** — компилятор проводит анализ кода и оптимизирует вычислительные блоки (например, заменяет циклы сложения на прямое умножение или разворачивает тело цикла), что делает ассемблерный код короче и быстрее.
