**Ответ.**

C++, команда `g++ task2.cpp`:

```
task2.cpp: In function 'int main()':
task2.cpp:3:13: error: expected ';' before 'b'
    3 |    int c=a++b;
      |             ^
      |             ;
```

(точная формулировка зависит от компилятора: clang, например, пишет `error: expected ';' after expression`, но смысл один и тот же)

Python, команда `python task2.py` — ошибок нет, программа отрабатывает молча. Добавил в конец `print(c)` — выводится `3`.

Разбиение на токены.

C++:

```
int  main  (  )  {  int  a  =  1  ,  b  =  2  ;  int  c  =  a  ++  b  ;  return  0  ;  }
```

Python (токены конца строки видно, если прогнать файл через модуль `tokenize`):

```
a  =  1  NEWLINE
b  =  2  NEWLINE
c  =  a  +  +  b  NEWLINE
```

Объяснение. Лексический анализатор работает по правилу максимального соответствия (maximal munch): в каждую позицию он старается забрать самый длинный возможный токен.

В C++ `++` — самостоятельный токен (оператор инкремента), поэтому фрагмент `a++b` режется как `a`, `++`, `b`. Получается законченное выражение `a++` (постфиксный инкремент), сразу за которым стоит идентификатор `b` — а между двумя выражениями нет ни оператора, ни `;`. Синтаксический анализатор это место проглотить не может, отсюда `expected ';' before 'b'`.

В Python токена `++` не существует в принципе, поэтому `a++b` разбивается как `a`, `+`, `+`, `b`, то есть как `a + (+b)`: первый плюс — бинарное сложение, второй — унарный плюс, применённый к `b`. Выражение полностью корректно: `c = 1 + 2 = 3`.

### Задание 3 **(2)**
*Рассмотрим следующую программу на языке С++.*
```
int main() {
   int a=1, b=2;
   int c=a+++b;
   return 0; 
}
```
*Запишите эту программу, выполните ее трансляцию и запустите. Проверьте, чему будут равны значения переменных после исполнения этой программы.
Разбейте эту программу на токены и объясните ее работу.*

*Можно ли изменить разбиение этой программы на токены, вставляя пробелы? Если да, то выполните эти изменения и проверьте работу измененной программы.*

**Ответ.**

Чтобы увидеть значения переменных, добавил вывод на экран:

```cpp
#include <iostream>
using namespace std;

int main() {
   int a=1, b=2;
   int c=a+++b;
   cout << a << " " << b << " " << c << endl;
   return 0;
}
```

Программа компилируется без ошибок и печатает:

```
2 2 3
```

То есть после исполнения `a = 2`, `b = 2`, `c = 3`.

Токены строки с присваиванием:

```
int  c  =  a  ++  +  b  ;
```

Опять срабатывает maximal munch: после `a` лексер видит `+`, пробует достроить токен подлиннее — `++` существует, а `+++` уже нет, поэтому забирается `++`, а третий `+` остаётся отдельным токеном. Выражение читается как `(a++) + b`:

- `a++` — постфиксный инкремент: возвращает СТАРОЕ значение `a` (то есть 1), а саму переменную увеличивает до 2;
- `c = 1 + b = 1 + 2 = 3`;
- переменная `b` не затрагивается.

Можно ли поменять разбиение пробелами? Да. Например, так:

```cpp
int c = a+ ++b;
```

Теперь токены — `a`, `+`, `++`, `b`, и выражение превращается в `a + (++b)` — префиксный инкремент: сначала `b` увеличивается до 3, потом возвращается новое значение. Проверил запуском, программа выводит:

```
1 3 4
```

То есть `b = 3`, `c = 1 + 3 = 4`, а `a` осталась равной 1. Из одной и той же последовательности символов плюсы собрались в совсем другие токены — получилась другая программа.

(Вариант `a++ +b` ничего не меняет: разбиение и так было `a ++ + b`, пробел между `++` и `+` стоит «бесплатно».)

### Задание 4 **(2)**
*В каком случае круглые и квадратные скобки являются операторами?
Приведите примеры фрагментов программ, в которых круглые скобки являются оператором и примеры 
программ, в которых они оператором не являются.*

**Ответ.**

Круглые скобки — оператор, когда обозначают вызов функции. Квадратные — оператор индексации (взятия элемента массива). Оба — постфиксные операторы с наивысшим приоритетом и ассоциативностью слева направо.

Скобки как оператор:

```cpp
int y = sqrt(25);   // () — оператор вызова функции
int v = a[i];       // [] — оператор индексации, по стандарту это то же, что *(a + i)
```

```python
f(x)        # () — вызов функции
lst[0]      # [] — взятие элемента списка
d["key"]    # тот же оператор [], только для словаря
```

Скобки НЕ оператор:

```cpp
int y = (1 + 2) * 3;   // группировка, меняет порядок вычислений
if (x > 0) { }         // часть синтаксиса инструкции if
while (i < n) { }      // то же самое для while
int a[10];             // квадратные скобки в описании массива — обращения к элементу нет
void f(int x);         // список параметров в объявлении функции
```

```python
y = (1 + 2) * 3     # группировка
nums = [1, 2, 3]    # литерал списка, [] здесь не взятие элемента
if (x > 0):         # скобки просто для читаемости
```

Простой способ проверить: если слева от скобок стоит объект/выражение, к которому скобки «применяются» (чтобы вызвать его или взять у него элемент) — это оператор; если скобки приклеены к ключевому слову (`if (...)`, `while (...)`) или просто сгруппировали кусок выражения — то нет.

### Задание 5 **(3)**
*Рассмотрим следующую программу на языке Python.*
```
print(*map(sum,zip(
    *[map(int,input().split()) for i in (1,2,3)]
    )))
```
*Найдите в этой программе ключевые слова, идентификаторы, литералы, операторы.
Какие из идентификаторов задают переменные, а какие - имена функций и методов?
Перечислите все функции, которые вызываются в этом фрагменте кода и их параметры.
Что делает эта программа, и как она приходит к результату?*

**Ответ.**

- **Ключевые слова:** `for`, `in`. Всё остальное похожее на «служебное» здесь ключевыми словами не является.
- **Идентификаторы:** `print`, `map`, `sum`, `zip`, `int`, `input`, `split`, `i`.
- **Литералы:** `1`, `2`, `3` — целочисленные литералы; вместе со скобками они образуют кортеж `(1,2,3)`.
- **Операторы и спецсимволы:** `*` (встречается дважды, и это НЕ умножение, а распаковка последовательности), `.` (доступ к методу), `( )` (вызовы и группировка), `[ ]` (генератор списка).

Из идентификаторов переменной является только `i` — переменная цикла генератора (причём само её значение нигде не используется, она нужна лишь чтобы повторить действие три раза). Остальные идентификаторы — имена функций и методов: `print`, `input`, `sum`, `zip`, `split` (метод строки); формально `int` и `map` в Python — классы, но используются здесь как вызываемые объекты.

Что и с какими параметрами вызывается (в порядке выполнения, т.е. изнутри наружу):

1. `input()` — без параметров; читает строку из ввода.
2. `input().split()` — метод `split()` вызывается на введённой строке без параметров и рубит её по пробелам на список слов.
3. `int(слово)` — один параметр, строка; превращает слово в число. Вызывается неявно, внутри `map`.
4. `map(int, список_слов)` — два параметра: функция `int` и итерируемый объект; возвращает объект-итератор чисел.
5. Генератор `[ ... for i in (1,2,3) ]` повторяет пункты 1–4 трижды и складывает результаты в список — то есть программа ждёт ТРИ строки ввода и получает список из трёх `map`-объектов.
6. `*` перед этим списком распаковывает его, поэтому `zip` получает три отдельных аргумента: `zip(строка_1, строка_2, строка_3)`.
7. `sum(t)` — один параметр, кортеж чисел; возвращает сумму. Тоже вызывается неявно, через `map`.
8. `map(sum, zip(...))` — параметры: функция `sum` и zip-объект.
9. Вторая `*` распаковывает полученный итератор в аргументы `print`.
10. `print(значение_1, значение_2, ...)` — печатает их через пробел.

Что программа делает: читает 3 строки чисел и выводит суммы по столбцам. Как она к этому приходит: каждая строка отдельно превращается в последовательность чисел; затем `zip(*три_строки)` «транспонирует» их — собирает в кортежи первые элементы всех строк, вторые и т.д., то есть превращает строки в столбцы; `sum` складывает числа каждого столбца; `print` выводит эти суммы.

Проверка:

```
ввод:          вывод:
1 2 3          12 15 18
4 5 6
7 8 9
```

### Задание 6 **(2)**
*Как можно записывать комментарии на С++?*

*Какие из приведенных ниже примеров являются синтаксически неверными (вызывают ошибки при трансляции)?
Почему? Как работают синтаксически верные примеры?*

**Ответ.**

В C++ комментарии бывают двух видов:

- строчные: `// ...` — от двух слешей до конца строки;
- блочные: `/* ... */` — могут занимать несколько строк, но важно: они НЕ вкладываются друг в друга.

Ключевой момент для разбора примеров: комментарии вырезает лексер ещё до синтаксического анализа, причём строковые литералы распознаются раньше комментариев. Поэтому всё зависит от того, что лексер увидел первым.

1) **Верный** (но с подвохом):

```
cout<<"Hello /* Это комментарий */ world";
```

Ошибки нет, потому что `/* */` находится внутри строкового литерала — лексер уже понял, что это строка, и искать в ней комментарий не будет. Никакого комментария тут на самом деле нет, это просто текст. Программа честно выведет: `Hello /* Это комментарий */ world`.

2) **Неверный:**

```
// /*
 Это комментарий
*/
```

`//` в первой строке глотает всё до конца строки вместе с `/*` — блочный комментарий так и не открылся. Вторая строка остаётся обычным кодом (два непонятных идентификатора подряд), а `*/` в третьей строке остаётся без пары. g++ ругается примерно так: `error: expected primary-expression before '/' token` (плюс ошибки про необъявленные идентификаторы выше).

3) **Неверный:**

```
/* Я комментирую программы /* комментарий */ */
```

Блочный комментарий не умеет вкладываться: он открывается у первого `/*` и закрывается у ПЕРВОГО же `*/`. После него остаётся хвост ` */` — это уже мусорные токены вне комментария, ошибка трансляции (`expected primary-expression before '/' token`). Если нужен комментарий внутри комментария, работает только схема «`//` внутри `/* */`», а не наоборот.

4) **Верный:**

```
// Я комментирую программы /* комментарий */  
```

Строчный комментарий съедает всё до конца строки, включая `/* */` — те внутри него ничего не значат. Пример компилируется и просто ничего не делает.

5) **Неверный:**

```
/* Я комментирую свои программы
// Это комментарий до конца строки */
*/
```

Блочный комментарий начинается в строке 1. Пока он не закрыт, `//` внутри него — обычный текст, лексер его «не слушает». На самом деле комментарий заканчивается у `*/` в конце строки 2. Оставшийся в строке 3 `*/` — лишние токены, ошибка компиляции.

Итого: синтаксически верны примеры 1 и 4, ошибки в примерах 2, 3 и 5.

### Задание 7 **(4)**
*Найдите в стандарте С++*

[http://www.open-std.org/jtc1/sc22/wg21/docs/papers/2017/n4659.pdf]

*в приложении* **A.5** *формальные синтаксические правила для 
инструкций циклов* **iteration-statement.** *Опишите на естественном языке каждую строчку
из этих правил. Для каждой строчки из правила приведите короткий пример фрагмента программы,
которая построена по этому правилу.*

**Ответ.**

Нашёл: приложение A (Grammar summary), подраздел **A.5 Statements** [gram.stmt]. Там записано:

```
iteration-statement:
    while ( condition ) statement
    do statement while ( expression ) ;
    for ( for-init-statement condition_opt ; expression_opt ) statement
    for ( for-range-declaration : for-range-initializer ) statement
```

(индекс *opt* означает, что этого элемента может не быть)

Как видно из правил, есть **4** инструкции циклов.

Первый вид — цикл **while** (цикл с предусловием), который соответствует строке правила

```
while ( condition ) statement
```

Формат записи (по правилу): ключевое слово **<<while>>**, в круглых скобках условие **<<condition>>**, далее инструкция **<<statement>>** — тело цикла. Пока условие истинно, тело повторяется; если условие ложно с самого начала — тело не выполнится ни разу.

Пример фрагмента программы.

```
int n = 100;
while (n > 0) {
  cout << n % 10;
  n /= 10;
}
```

Второй вид — цикл **do-while** (цикл с постусловием), который соответствует строке правила

```
do statement while ( expression ) ;
```

Формат записи (по правилу): ключевое слово **<<do>>**, затем инструкция-тело **<<statement>>**, затем ключевое слово **<<while>>**, в круглых скобках выражение **<<expression>>** и обязательная в конце точка с запятой. Условие проверяется ПОСЛЕ тела, поэтому тело гарантированно выполнится хотя бы один раз.

Пример фрагмента программы.

```
int x;
do {
  cout << "Vvedite polozhitelnoe chislo: ";
  cin >> x;
} while (x <= 0);
```

Третий вид — классический цикл **for**, который соответствует строке правила

```
for ( for-init-statement condition_opt ; expression_opt ) statement
```

Формат записи (по правилу): ключевое слово **<<for>>**, в круглых скобках через точку с запятой три части: **<<for-init-statement>>** — инициализация (обычно объявление и присваивание счётчика, выполняется один раз до начала цикла), **<<condition_opt>>** — условие продолжения (может отсутствовать), **<<expression_opt>>** — выражение шага (тоже может отсутствовать, выполняется после каждой итерации); далее инструкция-тело **<<statement>>**. Если условие опущено, оно считается истинным — поэтому `for (;;)` это бесконечный цикл.

Пример фрагмента программы.

```
int s = 0;
for (int i = 1; i <= 100; i++) {
  s += i;
}
```

Четвёртый вид — цикл **for по диапазону** (range-based for, появился в C++11), который соответствует строке правила

```
for ( for-range-declaration : for-range-initializer ) statement
```

Формат записи (по правилу): ключевое слово **<<for>>**, в круглых скобках **<<for-range-declaration>>** — объявление переменной, затем двоеточие и **<<for-range-initializer>>** — диапазон (массив или контейнер), далее инструкция-тело **<<statement>>**. Переменная по очереди принимает значения всех элементов диапазона.

Пример фрагмента программы.

```
int a[] = {3, 1, 4, 1, 5};
for (int x : a) {
  cout << x << " ";
}
```

### Задание 8 **(3)**
*В следующей программе постройте абстрактное синтаксическое дерево для выражения,
вычисляющего значение переменной* **a**.
```
int main() {
int a,x,y,z;
cin >> x >> y >> z;
a = -x+y*(z-1);
}
```

**Ответ.**

Выражение — `a = -x + y * (z - 1)`. По приоритетам операторов складывается такой порядок: скобки `z - 1`, унарный минус `-x`, умножение `y * (z-1)`, сложение, и в самом конце — присваивание (у `=` самый низкий приоритет из всех операторов в выражении). Поэтому корнем дерева будет оператор присваивания.

Абстрактное синтаксическое дерево:

```
                      =
                   /     \
                  a       +
                       /     \
              (унарный) -     *
                  |        /     \
                  x       y       -
                               /     \
                              z       1
```

По уровням:

- корень — присваивание `=`; левый потомок — идентификатор `a` (куда записываем);
- правое поддерево — вычисляемое выражение, его корень — `+` (складываем два слагаемых);
- левое слагаемое — унарный минус, применённый к `x` (у унарного оператора один потомок);
- правое слагаемое — умножение: `y` и результат вычитания `z - 1`.

Вычисляется дерево снизу вверх, от листьев к корню: сначала считаются `-x` и `z - 1`, потом произведение `y * (z - 1)`, потом сумма, и в конце результат записывается в `a`.

Проверка на числах: пусть ввели `x = 2, y = 3, z = 4`. Тогда `a = -2 + 3 * (4 - 1) = -2 + 9 = 7`. Запустил программу с таким вводом — выходит 7, сходится.
